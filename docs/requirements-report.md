# 高校社团活动全流程管理系统需求分析报告

需求基线 v1.0 · 提交前草稿

## 1. 背景与目标

高校社团办理一场活动，通常需要协调社团资格、活动审批、场地、报名、签到和学分。场地被临时征用时，学校需要了解哪些活动受到影响，以及保留原定时段的替代方案。系统将这些操作关联到活动记录，使审批、预约、参与和结果可以追溯。社团负责人可以用 DeepSeek 生成初稿，也可直接填写活动策划。

需求来自课程任务和项目的冻结讨论。将典型场景拆成准备、执行、收尾三个阶段，再转为带优先级编号的需求和验收用例。项目按个人课程原型的范围组织。

## 2. 参与者与场景

| 参与者 | 主要操作 |
|---|---|
| 学生 | 浏览公开信息、申请成立社团、报名或取消、查学分、提交评价 |
| 社团负责人 | 管理自己已获批社团的活动策划、提交审批、申请场地、交年审材料 |
| 学校管理员 | 审核社团及活动、维护场地、审批预约、处理征用、登记签到、确认完成、配置学分、看评价和统计 |

准备阶段先审核社团，负责人完成策划并提交，管理员审批活动后可申请场地。执行阶段对已通过审批的活动开放报名，管理员在活动时段内登记有效报名学生的签到。收尾阶段确认活动完成，系统认定学分，参与者提交评价，管理员按学期、社团和活动类型查看数据。

## 3. 功能需求及优先级

| 模块 | P0 | P1 |
|---|---|---|
| 社团 | CLUB-01 至 CLUB-03，申请、审核、查询 | CLUB-04 至 CLUB-05，年审提交和处理 |
| 活动 | ACT-01 至 ACT-08，创建、AI 草案、编辑、审批、浏览、报名、名单、签到和完成 | — |
| 场地 | VEN-01 至 VEN-06，维护、查询、申请、冲突检测、审批、替代匹配 | VEN-07，临时征用 |
| 学分 | CREDIT-02 至 CREDIT-03，自动认定与个人查询 | CREDIT-01、CREDIT-04，规则配置和按学期汇总 |
| 评价 | — | EVAL-01 至 EVAL-04，评分、文字、查询和平均分 |
| 统计 | — | STAT-01 至 STAT-05，按学期、社团、类型、参与和学分统计 |

P0 支撑主要流程，P1 需要可演示的基本功能。本期范围为单体课程原型。校园统一身份认证、教务集成和复杂调度优化属于后续范围。

## 4. 核心业务规则

- 社团通过审核后才可提交活动。活动审批通过后才公开，报名人数不得超过上限，每位学生每场活动只有一条报名记录。活动开始后关闭报名。
- 场地在重叠时段只能有一条有效预约。临时征用触发替代协调，候选必须满足容量和必要设备。协调优先最大化按原时段成功安排的活动数，同等结果比较优先级及申请顺序。管理员确认并提交后才变更预约。
- 学分依据有效报名、签到和活动完成状态认定，每人每场活动最多认定一次，并保存来源活动和认定时间。评价来自已参加的学生，每人每场活动最多一次。
- DeepSeek 仅接收活动构想并生成结构化草案。负责人确认后保存，审批、容量、冲突、签到和学分由授权人员和后端规则处理。超时及校验错误应给出明确提示。

## 5. 非功能需求与验收

| 编号 | 需求 | 验收依据 |
|---|---|---|
| NFR-01 | 易用性 | 页面支持角色操作，显示成功和错误 |
| NFR-02 | 持久化 | 应用重启同一数据库后可读取原记录 |
| NFR-03 | 一致性 | 预约冲突、重复报名、签到、学分均有测试 |
| NFR-04 | 权限 | 学生访问管理员写入接口应被拒绝 |
| NFR-05 | 异常反馈 | 校验、DeepSeek 超时及数据库写入异常有反馈 |
| NFR-06 | 可维护性 | 路由、数据模型、外部服务和场地规则分层 |
| NFR-07 | 可测试性 | Pytest 覆盖核心规则，真实 API 单独验收 |
| NFR-08 | 可部署性 | 按 README 从干净环境安装并启动 |
