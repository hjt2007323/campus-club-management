## 在 TRAE 中提交的任务

> 实现 `app/services/venue_matching.py` 中的 `recommend_venues`。输入是已经通过容量、设备、现有预约及学校征用校验的候选集合。返回 `{预约编号: 场地编号}`。空输入或无可分配结果返回空字典。同一场地可以接待时间不重叠的多个活动，时间采用左闭右开区间，活动保持原时段。
>
> 先最大化安置成功的活动数量。数量相同，按优先级从高到低、预约编号从小到大比较是否安置该活动，同一优先级优先安置较早提交的预约。安置的活动集合相同，按同一顺序优先选择编号较小的场地。用适合课程演示的小规模确定性方法实现并说明复杂度。
>
> 运行 `python -m pytest -q tests/trae_venue_matching.py`。重点查看两场活动争用投影网络教室的场景。其中只有需要网络的活动必须使用那间教室，另一场去备用投影教室，建议方案应当保留两场。两场原始预约只有在管理员确认后才替换。

实际修改可集中在这个文件。系统已把函数接到协调预览，确认时还会在数据库事务中检查容量、设备和占用状态。现有用例覆盖最大安置数、同数量时的优先级、同优先级时的申请顺序、相邻时段和接口确认。
