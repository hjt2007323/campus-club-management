# 高校社团活动全流程管理系统验收记录

2026-11-21 · Windows · Python 3.14.6 · SQLite

## 运行记录

- Pytest 常规回归共 10 项通过。显式启用的在线 API 用例在常规命令中跳过。测试工具有一条 Starlette TestClient 对 httpx 的弃用提示。
- Chrome 浏览器通过本地 Uvicorn 服务执行主流程。从社团申请、真实 DeepSeek 策划、人工保存和审核，走到预约、征用后的人工换场、报名、签到、学分、评价和统计。测试使用独立 SQLite 数据库，以可控时钟推进到活动开始和结束。已验证宽度为 395 像素时场地页面无需横向滚动。
- TRAE 开发截图记录了当时 7 项专项通过。后续复核发现一个平局排序问题。修正后新增回归用例，专项复验 8 项通过。

## 业务验收

| 编号 | 前置条件和操作 | 实际结果 | 结论 |
|---|---|---|---|
| T01 至 T03、B01、B15 | 学生申请，管理员通过，查询公开列表，尝试越权审核或提前创建活动 | 状态先待审核后通过，公开列表只展示已获批社团。越权返回 403，社团未审时创建返回 409 | 通过 |
| T04 | 社团提交同一年审两次，管理员处理 | 重复提交返回 409，第二个学生无法替社团提交，获批结果可查询 | 通过 |
| T05 至 T07、B13、B14 | 浏览器真实生成草稿。再分别模拟无效模型输出和超时 | 生成后活动列表仍为空，人工编辑并确认后才保存。未确认返回 422，异常请求返回 502 或 504 且未写入活动 | 通过 |
| T08、T09、B02 | 草稿提交审批，退回并重提，切换学生浏览或报名 | 未审批时不公开且无法报名，获批后可浏览和报名 | 通过 |
| T10、T11、B08 | 多个学生报名，达到上限后试报，取消一人后重报，管理员查看名单 | 无重复记录，只有有效报名出现在名单。并发争抢最后一席只有一个成功 | 通过 |
| T12、B09 | 管理员在活动时段内登记签到两次，结束后确认完成 | 重试保留首次登记时间，取消报名无法签到，结束前不能完成 | 通过 |
| T13 至 T15、B03、B04 | 建场地，两笔预约并发申请重叠时段，再申请相邻时段 | 并发结果 201 和 409，待审已锁定时段。相邻时段可用，审核通过后公开场地 | 通过 |
| T16、B05、B06 | 查询原时段的替代场地 | 排除设备不足、容量不足和时段占用的场地 | 通过 |
| T17 | 管理员征用两个场地，预览后提交带冲突的换场，再提交有效方案 | 两条原预约进入待协调状态。冲突时整批回滚，预览后新占位也会挡住提交。有效批次保留原时段并追溯原预约 | 通过 |
| B07 | 请求多活动批量建议，期望优先保留两场活动 | 两场均成功安排，优先级和申请顺序先于场地编号，专项通过 | 通过 |
| T18 至 T20、B10、B11 | 配置 1.25 学分，完成活动两次。查已签到、未签到和已取消学生的记录 | 仅发放给已签到者，保留来源活动和认定时间，按学期汇总，无重复认定 | 通过 |
| T21、T22、B12 | 已签到学生评分并评价，未签到学生尝试评价，管理员查看平均分 | 首次评价保存，重复评价返回 409，非参与者返回 403，平均分来自已保存评分 | 通过 |
| T23 | 查询各维度统计，换到无活动学期 | 活动、报名、签到及学分来自实际记录，空学期返回零 | 通过 |
| E2E-01、E2E-03 | 在浏览器操作完整活动并使用真实 DeepSeek | 社团审核、人工保存、审批、预约、报名、签到、学分、评价和统计均闭环 | 通过 |
| E2E-02 | 双社团预约冲突、征用、候选筛选、替代确认 | 冲突检测、批量建议和管理员确认均通过接口用例。浏览器已验证人工换场 | 通过 |
